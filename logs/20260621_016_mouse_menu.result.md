## 指示の要旨

`logs/20260621_016_mouse_menu.request.md` 参照。自/敵ユニットの状況と可能な操作を明示し、可能な操作をマウスから
決定できるメニューを作る。左下に自ユニット一覧、右下に可視敵ユニット一覧、選択ユニットの右上にマップ重畳の行動メニュー、
ターン終了ボタン、ショートカットキー併記、ユニット外マスクリックで選択解除、可視敵クリックで右下一覧の強調（敵も選択可）。
必要な設計変更・作業リスト更新を行い、todos.md は完了済みを整理して本件を最優先にする。不確定点は指示者に問い合わせるか tbd へ。

## 指示者への確認と回答

設計を確定する前に、todos の骨格を左右する2点を `AskUserQuestion` で確認した。

1. **UI 実装方式**: 「今回がフレームワーク導入の判断時点か（D-15）」。
   - 指示者から「ゲーム UI は Canvas ベースだが Vue が適すか」と逆質問あり。
     → 「Canvas（マップ）はフレームワーク管理外で恩恵なし、DOM 側（パネル＋メニュー＋ボタン）は一方向再描画で足り、
     規模が小さく Vue の旨味が出にくい」と整理して回答。
   - **回答: 素の TS + DOM を継続**（→ `decisions.md` D-17 に記録）。
2. **操作と選択解除の競合**（「空マスクリックで解除」と「隣接マスクリックで移動/攻撃」）。
   - **回答: ハイブリッド**（隣接の有効マスは移動/攻撃、行動対象でない空マスで解除）（→ `design.md §12.5`）。

## 設計上の判断メモ（実装担当への申し送り）

- 既存クエリ `canMove/canAttack/canGather/canBuildRobot/canEndTurn/canUndo` は実装済みで T-6 のメニュー有効条件にそのまま使う。
  T-1 で追加する `isOnResourceTile/isPlayerOnPod` は**メニュー項目の表示条件**（理屈上の可否）専用で、有効条件とは別系統。
- 「ターン終了時 HP 遷移」は `previewEnemyPhase()` の `damage.{player,pod,robots}` を引いて算出。自ユニット側のみ非 0、敵側は 0（G-11）。
- 既存の HUD 暫定実装（`Actions:` 行・採取/建造 true/false）は本タスクの T-4〜T-6 でパネル/メニューへ発展させる位置づけ。
