# 20260621_010 アンドゥ＋敵相プレビューの計画化（design 工程）

- 実施日時: 2026-06-21
- 使用モデル: Claude Opus 4.8（its-design スキル文脈）
- 契機: 指示者が `web` コンテナ（`http://localhost:8080`）でマウス操作の手動通しプレイ（移動→ゴール到達=勝利）を確認。
  併せて「行動を確定する前に、そのターンの敵の行動と結果まで予見でき、修正（アンドゥ）できる」ことが MVP 最終で望ましいと要望。

## 回答（現状把握）

- **アンドゥ・敵相プレビューはいずれも未実装**。`Command` 型に Undo 相当はなく、`dispatch` は即時適用。
- 決定的予見可能性は原則として記録済み（D-13・`rule.md §7.2`・`design.md §15`）だったが、操作機能（アンドゥ/プレビュー）の
  設計・タスクには未分解だった。現行ターン構造は「プレイヤー相 → EndTurn 後に敵相」のため、確定前プレビューには追加実装が要る。

## 反映内容（計画化）

- **decisions.md D-16** を追加: アンドゥ（プレイヤー相内スナップショットスタック・EndTurn でクリア）と
  敵相プレビュー（敵相を「試算＝純・emit なし」と「適用＝emit あり」に分離し決定的に予測）を MVP 最終目標として確定。
  既存アーキテクチャ（決定的 D-06/D-11・純データ D-08・敵相の副作用が emit に限定）が安価に支える点を根拠に明記。
- **design.md §6.1** 新設（アンドゥと敵相プレビューの設計）・**§7** の `GameService` I/F に `undo()` / `previewEnemyPhase()` を追記。
- **todos.md** に「予見可能性タスク（MVP最終目標・D-16）」を追加: 敵相試算の純関数分離 → `undo()` → `previewEnemyPhase()` 公開 →
  UI（プレビュー描画・Undo 操作）。冒頭「直近の状況」と Phase 4 手動確認に web:8080 での勝利経路確認を記録。

## 留意

- プレビューの表示粒度（移動先のみ／被ダメ込み 等）と Undo の操作割り当ては実装時調整（D-16）。純粋仕様の決定は不要なため tbd 化はしない。
- 実装着手は G-02 反映タスク（最優先）と整合させて行うのが望ましい（敵相の被ダメ宛先＝ポッド重なりが試算にも効くため）。
