# 20260621_011 G-02 反映: ポッド/敗北モデルの実装更新（implement）

## 概要・目的

`decisions.md` D-12（指示者判断 G-02/G-05/G-08）で確定した「可動ユニットと固定建造物の分離・ポッド破壊で敗北」モデルへ、
既存実装（Phase 1〜4 の一部）を追従させる。これは MVP コアモデルの変更であり、後続の `20260621_012`（予見可能性）の前提となる
**最優先タスク**。`its-implement` 工程として実施する。

## 作業対象（todos.md の該当セクションが一次指示）

**`todos.md` の「G-02 反映タスク: ポッド/敗北モデルの実装更新（design タスク `20260621_008`・最優先）」を正典の作業リストとする。**
本指示書はそのスコープ・順序・完了条件を補足するもので、各タスクの API・要点・テストは todos.md の記述に従う。

実施対象（todos.md の順で）:

1. `GameState.pod` の導入と `newGame` 構築 — `src/application/GameService.ts`・`state.ts`
2. 敗北判定にポッド破壊を追加（`evaluateStatus` に `podAlive`）— `src/domain/rules/victory.ts`（呼び出し側 turnEngine/GameService も）
3. 重なり時の被弾はポッドへ — `src/application/turn/turnEngine.ts`
4. 敵の攻撃/接近対象にポッドを含め優先度（player>pod>robot）を適用 — `src/application/turn/enemyAi.ts`
5. 描画/HUD のポッド対応（ポッドHP表示・敗北表示）— `src/presentation/CanvasRenderer.ts`・`Hud.ts`

併せて、Phase 5 着手前提のレビュー指摘 **[必須]「`AttackUnit` のフレンドリーファイア防止」**（todos.md 末尾レビュー指摘節）も
本タスクで対応してよい（ロボット導入前に潰しておくと安全。`isPlayerSide` 判定で `target-not-enemy` を返す）。
