## 実装内容

### `src/application/state.ts`

`GameState` / `Phase` 型を配置。`GameStatus` は `domain/rules/victory` から再利用（domain→application の依存方向を維持）。

### `src/application/commands.ts`

`Command` / `RejectReason` / `CommandResult` 型を `types-reference §3` 通りに配置。

### `src/application/events.ts`

`DomainEvent` 型を `types-reference §3` 通りに配置。

### `src/application/util.ts`

- `minBy<T>(arr, rank)`: タプル辞書順で最小要素を選択。同順位は配列の先頭側を採用（安定）。
- `occupantAt(units, h)`: 指定 hex にいる生存ユニットを返す（敵味方問わず）。

### `src/application/turn/enemyAi.ts`

`decideEnemyAction(state, enemy)` を純粋関数として実装。

- 隣接する自ユニットがいれば id 昇順で攻撃。
- 視界内の最近自ユニットを `minBy` で選択。
- `HEX_DIRECTIONS` 順に進行先を評価し、最も target に近づく空き passable マスへ1歩移動。
- 該当がなければ待機。

### `src/application/turn/turnEngine.ts`

`runEnemyPhaseAndAdvance(state, emit)` を実装。

- 敵 id 列をループ前に確定し、`id` 昇順で処理。
- 各反復で敵の生存を確認。
- 敵相では勝利判定をせず、プレイヤー本体死亡で `lost`。
- ターンを進め、`turnState` を現在の player/robot から作り直す。
- `updateVisibility` で霧を再計算。
- `PhaseChanged` / `TurnAdvanced` / `FogRevealed` / `GameLost` 等を発行。

### `src/application/GameService.ts`

`GameService` クラスを実装。

- `static newGame(seed)`: 簡易マップ生成（半径3、中心に player、`(R,0)` に goal）。Phase 3 で `MapGenerator` と統合。
- `getState()`: `structuredClone` で読み取り専用スナップショットを返す。
- `subscribe(listener)` / `emit(event)`: イベント配信を `subscribe` に一本化（D-09）。
- `dispatch(cmd)`: `CommandResult` のみ返す。
  - `MoveUnit`: フェーズ/所有権/行動済み/移動力/checkMove を検証 → 移動 → 霧更新 → goal 到達で `GameWon`。
  - `AttackUnit`: フェーズ/所有権/行動済み/対象存在・隣接を検証 → 戦闘解決 → HP 反映/除去 → `CombatResolved`。
  - `EndTurn`: 敵相を実行。
  - `GatherResource` / `BuildRobot`: Phase 5 まで保留（`{ ok: true }` を返す）。

### `src/application/index.ts`

application 層の公開 API を re-export。

## 設計との乖離・補足

- `GameService.newGame` は Phase 3 の `MapGenerator` 完成までの簡易実装。シグネチャは `newGame(seed: number): GameState` で維持。
- `GatherResource` / `BuildRobot` は Phase 5 まで保留。`dispatch` は `{ ok: true }` を返す（未対応扱いにせず保留）。
- `GameService` 内で nest 攻撃も扱えるよう、`AttackUnit` は `state.units` と `state.nests` の両方を対象に検索。
- `structuredClone` の返り値は TypeScript 5.4 以降で正しく `GameState` と推論されるため、型アサーションは不要だった。
