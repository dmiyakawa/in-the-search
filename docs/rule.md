# ゲームルール

本ドキュメントは探索ゲームのルールの**正典**である。`design.md` は本ルールを実装に落とす設計を示す。
ルールと設計が食い違う場合、ゲーム仕様としては本ファイルを優先する（設計都合の差異は design.md 側で吸収する）。

現時点の記述は **MVP（最初のプレイアブルデモ）** のルールである。MVPの先で詳細化する論点は `tbd.md` を参照。

---

## 1. 目的

- プレイヤーは未知の惑星に不時着し、六角タイルマップ上を探索する。
- **勝利**: ゴール（宇宙船）タイルに自ユニットのいずれかが到達する。
  （将来は到達後に「修理」など複数の必須クエストが続く。MVP は到達＝勝利。`decisions.md` D-14）
- **敗北**: **プレイヤー本体（ロボットではない）の死亡**、または**脱出ポッドの破壊**のいずれかが満たされたとき
  （HPが0になる）。`decisions.md` D-12。

## 2. マップと座標

- 六角タイルマップ（pointy-top）。境界は有限領域（MVPは小さめの六角領域から開始）。
- 各タイルは地形 `passable`（通行可）/ `blocked`（通行不可）のいずれか（MVPは2種）。
- 特別タイル: `pod`（脱出ポッド＝開始拠点）/ `goal`（宇宙船）/ `nest`（敵の巣）。
  これらは**固定建造物**であり、その上には可動ユニットが**重なれる**（§5・§6）。
- 一部タイルには資源ノードがある。

### 2.1 ユニットと建造物の区別（重要）

- **可動ユニット**（player / robot / enemy）はマップ上を移動する。
- **固定建造物**（pod / goal / nest）はマップに固定され、能動的な操作はしない。
  - 脱出ポッド（pod）は **HP/防御を持ち破壊され得る**（敗北条件の一つ）。「動作しないユニット」とみなしてよいが、
    可動ユニットが重なれることが必須。
  - ゴール・巣などの建造物にも、プレイヤーや敵が重なれるケースが多い。

## 3. 霧（未探索）と視界

- 各タイルの可視性は `unknown`（未発見）/ `discovered`（発見済み・記憶）/ `visible`（現在視界内）。
- 自ユニット（プレイヤー本体・ロボット）の視界半径内（hex距離 ≤ 視界）のタイルが `visible` になる。
- 視界から外れた既知タイルは `discovered` に戻る。地形と特別タイルは記憶されるが、
  **そのタイル上の敵は `visible` のときだけ見える**。
- MVPは視線遮蔽（LoS）なし。半径内は素通しで可視。

## 4. ターン進行

1ターンは次の順で進む。

1. **プレイヤー相**: プレイヤーは自ユニット（プレイヤー本体・各ロボット）を操作する。
2. **敵相**: 各敵が自動で1ステップ行動する。
3. **解決**: 戦闘ダメージを確定し、HPが0のユニットを除去する。
4. **勝敗判定**: 後述の優先順位で判定する。
5. ターン数を進め、視界を再計算してプレイヤー相に戻る。

### 4.1 勝敗判定の優先順位（重要）

- **プレイヤー相で**自ユニットがゴールへ到達した場合、その瞬間に**即勝利**とし、敵相をスキップしてゲームを終了する。
- 上記以外で、敵相の解決後に**プレイヤー本体が倒れている、または脱出ポッドが破壊されていれば敗北**。
- 同一の解決内で勝利条件と敗北条件が同時に成立し得る場合は**勝利を優先**する。

## 5. 行動（プレイヤー相）

- **1タイルには最大1つの可動ユニットしか存在できない**（敵味方を問わず）。移動先・敵の進行先に他の可動ユニットが
  いるタイルへは入れない（「敵タイルへ移動不可」§6 もこの一般則の一部）。敵相でも、先に動いた敵が占有した
  タイルへ後続の敵は入れない。
- **固定建造物（pod / goal / nest）は占有判定に含めない**。可動ユニットは固定建造物の上に重なれる。
  特にプレイヤー本体はポッドに重なれる（その状態の被弾は §6 でポッドHPに入る）。
- プレイヤー本体は開始時にポッド上、または近傍からスタートする。
- 各自ユニットは1ターンに **移動力ポイント** を持つ（プレイヤー本体・ロボットで個別）。
- 1歩の移動（隣接 `passable` かつ**空き**タイルへ）で移動力を1消費する。
- 同一ターン内で複数の自ユニットを順に操作できる。各ユニットの残移動力は独立。
- 移動以外の行動（攻撃・資源採取・ロボット建造）は、そのユニットのそのターンの**行動を終了**させる
  （移動力の残りに関わらず、以後そのユニットはそのターン行動できない）。
- 「ターン終了」を宣言すると敵相へ進む。

## 6. 戦闘

- **敵タイルへは移動できない**。敵を攻撃するには、攻撃側が対象の敵に**隣接**している必要がある。
- 攻撃は攻撃側の `attack` 値ぶんの確定ダメージを与える（命中判定・乱数なし）。
  - 攻撃には**種類**があり、指定なき MVP は「近接」とする。既定の方向性（将来）として、プレイヤーは近接、
    **ポッドに重なっているプレイヤーは距離2まで対応可**、ロボットは近接/遠隔/遅延範囲などがあり得る（`decisions.md` D-14）。
- 敵相では、各敵は隣接する自ユニット（または重なられたポッド）がいれば攻撃する。いなければ
  **視界内**の最も近い対象（プレイヤー・ポッド）へ1歩近づく。**視界内に対象がいなければ待機**する。
  - **敵の攻撃優先度は プレイヤー > ポッド（基地） > ロボット**（同条件で複数を狙えるときの選好。将来この優先度を
    上書きする存在＝デコイ等はあり得る）。
  - プレイヤーがポッドに重なっている状態で攻撃を受けると、**ダメージはプレイヤーHPではなくポッドHPに入る**。
- HPが0になった可動ユニットは除去される。ポッドのHPが0になると敗北（§4.1）。
- 巣（`nest`）の破壊はMVPでは任意（攻撃で破壊できるが勝利には不要）。

### 6.1 敵相の決定性

- 敵は `id` の昇順で処理する。
- 接近対象が同距離で複数ある場合・進む隣接方向が同距離で複数ある場合は、
  近傍6方向の固定優先順位でタイブレークする。
- 確率的処理が必要な場合は固定シードの乱数（同一RNGストリーム）を用い、再現性を保つ。

## 7. 資源とロボット建造（MVP最小スライス）

- 資源は単一種。自ユニットが資源ノードのあるタイルで**採取**すると在庫に加算される。
- **ロボット建造**はプレイヤー本体が `pod` タイル上にいるときのみ行える。
- MVPの建造対象は探索用ロボット `scout` の1種類のみ。`scout` はプレイヤー本体より
  視界・移動力が高く、戦闘は不得手。
- 建造は資源を消費する。
- 建造された `scout` はポッド隣接の通行可能・空きタイルに配置される。建造したターンは行動済みで、次ターンから操作できる。

### 7.1 暫定数値（プレイ感に応じて調整。`tbd.md` G-04/G-09 参照）

- プレイヤー本体: HP=10 / 視界=2 / 移動力=2 / 攻撃=2
- 脱出ポッド（pod）: HP=20 / 防御=0（MVP は確定ダメージのため防御は未使用）/ 移動・攻撃なし（固定建造物）
- 敵: HP=4 / 視界=3 / 移動力=1 / 攻撃=3
- `scout`（探索用ロボット）: HP=3 / 視界=4 / 移動力=3 / 攻撃=1
- 資源採取: 1回で +5 / `scout` 建造コスト: 10
- マップ: 半径 R=6〜8 程度、障害物率・敵/資源密度はプレイ感で調整

> 開発時は少数の難易度プリセットよりも、上記パラメータを自由に変えて開始できる柔軟性を優先する（`tbd.md` G-09）。

## 7.2 決定的予見可能性（重要・将来にわたる原則）

- ユーザーの決定が同じなら、ゲームは開始から終了まで**決定的**に進む。
- あるターンでプレイヤーが行動を確定する前に、そのターンの敵・他ロボットの動作、巣からの生成などのイベント結果は
  **100%予見できる**ようにする（UI 上で移動先のプレビューや被ダメ予測を示せるのが望ましい）。
- これは「ランダムに見える挙動の禁止」ではなく、「同じユーザー決定なら結果は決定的で、決定後は正確に確認できる」という意味。
- イベントの結果は**実行タイミングに依らず同一**であることが望ましい（例: 「謎のほこら＝HPを一定失い、選べない
  ランダムな正効果を1つ得る。いつ実行してもそのゲーム内では同結果」）。RNG の引き方の設計指針は `decisions.md` D-13。
